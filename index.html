Privacy Policy — Quarry

Last updated: 28 September 2026 · Chrome extension “Quarry — Web Intelligence”

Quarry is a security reconnaissance extension for bug bounty and authorized penetration testing. This policy explains exactly what data the extension handles and where it goes.

Core principle: your data stays on your machine. Everything Quarry captures while you browse — resources, endpoints, secrets, request/response bodies, cookies, tokens, storage and the knowledge graph — is stored exclusively in your browser's local storage (chrome.storage.local). None of it is sent to us or to any server operated by the developer. There is no telemetry, no analytics, no account and no backend.

What leaves your machine, and where it goes

DataDestinationWhen
Page content/structure (snapshot) and your stated objective The LLM endpoint you configured (OpenAI, Anthropic, local Ollama, etc.) Only when you run the AI agent, using your own API key. Authorization headers, cookies, e-mail addresses, query tokens, JWTs and API keys are masked before sending. Page text can still contain personal data no pattern covers.
Your objective, the page URL and title, and short descriptions of candidate actions TypeSafe AI (Jev), only if you turn Use Jev on and save a TypeSafe key The same masking applies. Jev picks among a closed set of actions and does not receive the full snapshot.
Exports (ZIP) Downloaded locally by you Only when you click export

We do not proxy the LLM. When the agent runs, data goes directly from the extension to the AI provider you chose, authenticated with your own key. That provider's privacy policy governs that traffic.

Your LLM API key

Your API key is used solely to authenticate calls to the provider you configured. If you turn Jev on, the TypeSafe key is used only in the Authorization header of direct calls to https://api.typesafe.ai. Both keys stay in your browser's storage (chrome.storage.local) and are never sent to us.

Permissions and why they are needed

  • webRequest, <all_urls> — passively observe traffic to map the attack surface. This permission is read-only.
  • scripting and content scripts — instrument the page to capture endpoints, sinks and storage.
  • storage, unlimitedStorage — keep the recon session locally.
  • downloads — save exports to your disk when you ask for them.
  • declarativeNetRequest — optional block or mock rules you create yourself. Off until you add one.
  • tabs, webNavigation, sidePanel — UI and binding the session to the right site.
  • cookies — read cookie flags for the current site. Values stay local and are masked if quoted in an agent snapshot.
  • debugger — only while an agent run you started is in progress, and only to send real mouse and keyboard events to that tab. It is detached when the run ends or you stop it. Chrome shows “started debugging this browser” for that interval.

Retention and deletion

You are in control: the clear button wipes the session, and uninstalling the extension removes all local data. We keep no copy, because we never receive one.

Children

Quarry is a professional security tool and is not directed at children under 13.

Changes to this policy

If this policy changes, the “last updated” date above changes with it, and the new version is published at this same URL.

Contact

Questions about privacy? Use the Support tab on our Chrome Web Store listing — messages sent there reach the developer directly.

Política de Privacidade — Quarry (Português)

O Quarry é uma extensão de reconhecimento de segurança para bug bounty e pentest autorizado. Esta política explica exatamente quais dados a extensão manipula e para onde eles vão.

Princípio central: seus dados ficam na sua máquina. Tudo que o Quarry captura enquanto você navega — recursos, endpoints, segredos, corpos de requisição/resposta, cookies, tokens, storage e o grafo — é armazenado exclusivamente no armazenamento local do seu navegador (chrome.storage.local). Nada disso é enviado para nós nem para qualquer servidor do desenvolvedor. Não há telemetria, análise, conta ou backend.

Não intermediamos o LLM. Quando o agente roda, os dados vão direto da extensão para o provedor de IA que você escolheu, com a sua própria chave. A política de privacidade desse provedor se aplica a esse tráfego.

Sua chave de API do LLM

Sua chave é usada apenas para autenticar chamadas ao provedor que você configurou. Se ligar o Jev, essa outra chave vai só no cabeçalho Authorization das chamadas diretas para https://api.typesafe.ai. As duas ficam no armazenamento do navegador (chrome.storage.local) e nunca são enviadas a nós.

Permissões e por quê

  • webRequest, <all_urls> — observar o tráfego passivamente para mapear a superfície de ataque. Essa permissão é só leitura.
  • scripting e content scripts — instrumentar a página para capturar endpoints, sinks e storage.
  • storage, unlimitedStorage — guardar a sessão de recon localmente.
  • downloads — salvar as exportações no seu disco quando você pedir.
  • declarativeNetRequest — bloquear ou simular request só se você criar a regra. Desligado até lá.
  • tabs, webNavigation, sidePanel — interface e vínculo da sessão ao site correto.
  • cookies — ler as flags dos cookies do site atual. O valor fica local e é mascarado se aparecer no snapshot do agente.
  • debugger — só durante um run do agente que você iniciou, e só para enviar mouse e teclado reais àquela aba. Solta ao terminar ou ao parar. O Chrome mostra “started debugging this browser” nesse intervalo.

Retenção e exclusão

Você controla tudo: o botão de limpar apaga a sessão, e desinstalar a extensão remove todos os dados locais. Não guardamos cópia, porque nunca recebemos nenhuma.
